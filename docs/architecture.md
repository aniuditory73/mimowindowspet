# Архитектура MIMO

На момент аудита локальный каталог содержал два документа с требованиями. В `main` на GitHub был стартовый README. Windows x64, Rust и Slint остаются основой проекта.

- `ui/mimo.slint` описывает представления и действия интерфейса, `src/ui.rs` преобразует состояния в подписи и связывает оконные события.
- `src/app.rs` владеет состоянием приложения, передаёт команды исполнителю и обновляет представление в цикле событий Slint.
- `src/domain.rs` задаёт типы команд и допустимые переходы состояний. `src/router.rs` распознаёт полный текст поддерживаемой команды. `src/policy.rs` допускает только проверку отклика.
- `src/tasks.rs` выполняет по одной задаче. В интерфейсе одновременно учитывается до трёх задач, включая выполняемую. Отмена будит поток через канал, а UI отображает подтверждённый исполнителем результат.
- `src/storage.rs` читает и записывает версионированные настройки в отдельном потоке. `src/platform/windows.rs` получает LocalAppData через Windows Known Folders API и размещает окно с учётом рабочей области и DPI.
- `src/notes.rs` хранит заметки в подкаталоге `notes-v1` как отдельные файлы UTF-8. Имя файла создаётся приложением, а запись публикуется без замены существующего файла. Поиск выполняется в фоне, показывает до 30 результатов и проверяет отмену между файлами. Следующая версия формата должна отдельно перенести файлы из `notes-v1`.
- `src/files.rs` проверяет абсолютный путь локального диска и каждый каталог до корня. Перенос повторно открывает файл по дескриптору и сверяет том, идентификатор файла, размер и время записи. Windows отклоняет замену существующего назначения. Для отмены сохраняется список успешных переносов в текущем сеансе.
- `src/codex.rs` обнаруживает `codex.exe` в абсолютных каталогах `PATH`, проверяет справку и версию, проверяет MXC локальной командой и запускает Codex с профилем чтения. Фоновые потоки ограничивают объём вывода. Windows Job Object завершает привязанные дочерние процессы при отмене и тайм-ауте.
- `history-v1` хранит UTF-8 записи с видом операции и конечным статусом. Начальные и промежуточные состояния существуют в памяти. Формат следующей версии следует читать из отдельного каталога с явной миграцией.

## Решения первого этапа

Slint собирает интерфейс на этапе компиляции. Используются программный рендерер Winit, системные шрифты, доступность и встроенный трей Slint. `windows-sys` используется для размещения, округления окна и безопасного открытия настроек. Интеграция с Winit привязана к точной версии Slint, так как API доступа к событиям окна помечен как нестабильный.

Формат настроек v1 содержит `version=1`, ключ `corner` со значением `top-left`, `top-right`, `bottom-left` или `bottom-right` и необязательный ключ `pinned` (`true` по умолчанию, `false` для обычного режима окна). При смене схемы будущая версия должна прочитать и проверить предыдущий формат перед миграцией. При сохранении временный файл создаётся рядом с настройками с проверкой отсутствия совпадения. Приложение сбрасывает его содержимое на диск и заменяет файл настроек переименованием. Для чтения проверяются тип файла, reparse point и число жёстких ссылок. Каталоги открываются без перехода по reparse point, их дескрипторы удерживаются на время операции без разрешения на удаление. Несколько экземпляров могут сохранить разные значения, действует последнее успешное сохранение.

Закрепление меняет порядок только окна MIMO через Win32 без активации. Пока видимое окно закреплено, таймер Slint сверяет границы активного окна с границами монитора MIMO. Если активное окно покрывает монитор, MIMO уступает ему место до следующей смены фокуса или геометрии. Проверка использует геометрию Windows и не читает содержимое окон.

## Этапы и критерии приёмки

- [x] Этап 0. Аудит и выбор архитектуры.
- [ ] Этап 1. Островок, панель, системный трей, настройка угла, фоновая очередь, отмена и отображение результата проверки отклика. Реализация готова, осталось проверить меню трея в интерактивном сеансе Windows.
- [ ] Этап 2. Просмотр выбранной папки, классификация, перенос и переименование с предпросмотром, заметки с редактированием и возврат последней операции в сеансе реализованы. Удаление заметок и долговременный журнал возврата остаются открытыми.
- [ ] Этап 3. Обнаружение и запуск в режиме чтения реализованы. Проверка реального облачного ответа и более широкая поддержка версий CLI остаются открытыми.
- [ ] Этап 4. Хоткей и история добавлены. Упаковка, отдельная проверка Windows 10/11 и действия с выделенным текстом остаются открытыми.
- [ ] Этап 5. Анимации и поведение персонажа после функционального MVP.

Для файловых задач политика будет проверять чтение и запись относительно одобренных корней, а также повторно проверять путь перед изменением. Удаление, перезапись и пересечение разрешённых границ потребуют отдельного решения пользователя. Повышение прав и системные изменения запрещены в MVP. Для Codex потребуются ограничения поддерживаемой песочницы CLI. Промпт и рабочая папка сами по себе не изолируют внешний процесс.
